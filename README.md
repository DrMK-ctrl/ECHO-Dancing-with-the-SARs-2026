# ECHO — Dancing with the SARs

ECHO is a new, independent project exploring how to investigate Earth-surface change from Synthetic Aperture Radar (SAR) observations. It is being prepared for NASA Space Apps Challenge 2026.

The guiding question is: **what does an observed radar change support us in saying, and what remains uncertain?** A difference between observations is evidence of a change in radar response; by itself, it does not establish a physical cause.

## Project status

The implementation has ASF metadata discovery and a local investigation interface with on-demand catalog search. GCOV searches follow ASF CMR result pages up to 1,000 records and explicitly mark a result set that reaches that cap as potentially incomplete. The interface timelines returned observations, offers metadata-compatible pair candidates, and connects selection to source metadata and map footprints. The map can be panned by dragging or keyboard arrow keys, reset to its search extent, and used to draw a WGS84 search rectangle; the catalog dialog also accepts numeric WGS84 bounds without a pointer-drawn rectangle. Catalog results do not establish complete pixel coverage. A selected GCOV scene and AOI can request a bounded, authenticated backscatter window, choose an available real-valued diagonal polarization layer and A/B frequency, display geolocated product measurements on the map, inspect a pixel's value and quality codes, and export a checksummed source and processing record. ## Working principles

- Keep measured observations, derived quantities, interpretations, and hypotheses distinguishable.
- Select methods according to the documented contents and limitations of each data product.
- Preserve source, processing, configuration, and validation provenance for analytical results.
- Compare explanations and report inconclusive outcomes when evidence is insufficient.
- Evaluate any added analytical complexity against an appropriate baseline.
- Keep the application focused on civilian Earth observation and the selected SAR challenge.

## Development

Python 3.11 or newer is required. Python 3.14.4 was used for the initial implementation.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pytest
```

Run a metadata-only search around the Mozambique case:

```bash
.venv/bin/echo catalog \
  --longitude 33.5 --latitude -24.5 \
  --start 2026-01-01 --end 2026-01-31 \
  --maturity BETA \
  --output data/cases/mozambique-2026/catalog.json
```

For a read-only search of online ISRO Bhoonidhi NISAR S-SAR GCOV catalog items, use a registered Bhoonidhi account. The command prompts for the account ID and a non-echoed password, uses the short-lived token in memory, and can write a checksummed provenance envelope around the raw STAC response:

```bash
.venv/bin/echo bhoonidhi-search \
  --bbox 76.8 28.4 77.4 28.9 \
  --start 2026-07-01T00:00:00Z --end 2026-08-01T00:00:00Z \
  --output /tmp/echo-bhoonidhi-catalog.json
```

The query requests only `NISAR_SSAR_GCOV` items marked online, with a maximum of 500 results. It does not download products, evaluate provider QA, or authorize measurement. See the [S-SAR feasibility review](docs/research/2026-11-07-nisar-ssar-bhoonidhi-feasibility.md) for product and access limitations.

Open the local investigation interface from the repository root:

```bash
.venv/bin/echo serve
```

See the [deployment readiness note](docs/deployment-readiness.md) for current local launch requirements and the security gates needed before any judge-access build.

For a local, single-case walkthrough that blocks catalog/provider requests, analysis POSTs, and draft access, start the selected retained case in curated read-only mode:

```bash
.venv/bin/echo serve --read-only-demo \
  --case-file data/cases/iraq-2026-nisar-diagnostic/catalog.json
```

Then open <http://127.0.0.1:8765/>. The server binds to localhost by default and reads the selected catalog JSON without modifying it. In the default interactive mode, local investigation drafts can be saved, and catalog, QA, and measurement actions can contact external providers; do not expose that mode to a network. Curated read-only mode is restricted to loopback and one case, blocks provider and mutation endpoints, and denies local draft access. Its optional NASA GIBS backdrop may still make read-only image requests. In default mode, choose **Find observations** for a point search, or **Select Area** and drag a WGS84 rectangle on the map to search intersecting ASF footprints. Choose the date interval and GCOV maturity before submitting. Search results stay in browser memory for the current session; they are not written to the case record. Catalog search follows CMR pages up to 1,000 results and marks a result set potentially incomplete if it reaches that cap. The geographic view plots catalog footprints and the search location on a longitude/latitude grid. An optional NASA GIBS MODIS Terra true-color image provides optical context for the selected acquisition date; its request sends the map bounds and date to NASA. It is not NISAR data or an analysis input, and the grid remains available if the image is disabled or unavailable. A no-result search is shown explicitly. The catalog-level “challenge this finding” reflection is temporary browser-session input. In a linked assessment, each hypothesis also has a structured challenge form; export its human review notes as JSON to preserve them. A cited evidence item can be reclassified hypothetically to preview the deterministic disposition rule. The preview is not evidence validation and never changes the retained scientific assessment. Exported review notes can be re-imported only against the exact same case, assessment checksum, and evidence checksums; ECHO reruns each counterfactual before displaying it and rejects stale or altered results.

The curated Iraq NISAR read-only launch now opens with its retained HHHH measurement window already drawn on the map. This is the exact, checksummed 9,918-center preview recorded in the case bundle; it is a diagnostic observation with provider QA `FAIL`, not a temporal comparison. The interface labels the record as locally retained and performs no new ASF measurement request.

For a GCOV catalog result, select a WGS84 area and choose a catalog-supported polarization layer and frequency, then choose **Load Backscatter** for an authenticated bounded read of that diagonal gamma-zero layer and its product mask, number of looks, and exception mask. The map colors actual product values; it is not a browse image. ECHO obtains the provider QA summary first, records its checksum and source, grid, range-read, selection, and array provenance, and can export the complete preview record. A preview with provider QA `FAIL` is explicitly labeled **QA-held diagnostic preview** and is not promoted to comparison, event detection, or physical interpretation. This single-observation path establishes data access and rendering, not temporal change. Remote reads are capped at 65,536 pixels and reject unsupported layers or invalid geographic bounds. The catalog interface follows ASF's 250-product CMR pages up to a 1,000-result application cap; reaching the cap is surfaced as potentially incomplete, and the user can narrow the date or area query.

Select an observation and choose **Fetch QA** to retrieve its canonical ASF QA-summary CSV through the configured local Earthdata Login. The interface shows each provider check with retrieval provenance and a SHA-256 checksum. **Export Source Record** downloads a JSON evidence record joining the selected catalog query and feature with the provider response. The request is limited to a supported ASF NISAR GCOV product and the CSV reader is capped at 64 KiB. Provider QA remains distinct from ECHO's scientific suitability gates; a pass does not authorize measurement, and the QA request does not read HDF5 metadata or radar arrays.

The interface acknowledges NASA GIBS imagery as requested in the [GIBS data use guidance](https://nasa-gibs.github.io/gibs-api-docs/). See [Decision 0011](docs/decisions/0011-nasa-gibs-contextual-basemap.md) for the layer boundary and fallback behavior.

Catalog discovery does not need Earthdata credentials and does not download HDF5 products. Product download or streaming requires a local Earthdata Login configuration. Never put Earthdata credentials in this repository or paste them into chat.

The optional `nisar` extra provides an allowlisted metadata inspector and the `read_gcov_window` Python API for bounded raster-array access. For the pinned environment, install `requirements-nisar.lock` (the lighter base environment remains in `requirements.lock`). Inspect one ASF catalog scene with:

```bash
.venv/bin/echo inspect-product \
  --catalog data/cases/nepal-2026/catalog.json \
  --scene-id NISAR_L2_PR_GCOV_028_098_A_016_4005_DHDH_A_20260819T233918_20260819T233953_P05023_N_F_J_001
```

The command uses Earthdata Login through the local netrc file, validates the catalog URL against the ASF NISAR host, and reads only an allowlist from the HDF5 identification group using bounded HTTPS byte-range requests. The Python `read_gcov_window` helper accepts either explicit row/column slices or a WGS84 bounding box. Geographic selection reads bounded full coordinate vectors, maps the rectangle to a projected GCOV window, and returns a pixel-center mask for the exact requested area. Sample, coordinate-array, raster-memory, and remote-range budgets apply. The reader does not assess product QA or establish cross-date grid alignment. Data access does not clear a QA hold or establish that a product is suitable for science.

Inspect the matching ASF QA report and its versioned metadata cross-check with:

```bash
.venv/bin/echo inspect-qa-report \
  --catalog data/cases/istanbul-2026/catalog.json \
  --scene-id NISAR_L2_PR_GCOV_033_137_D_068_2005_DHDH_A_20261021T170432_20261021T170507_P05023_N_F_J_001
```

This command retrieves only the bounded QA PDF, records its source and checksum, verifies the report scene ID against ASF catalog metadata, and compares orbit, track, and frame values. Its source-code cross-check is diagnostic only; the PDF does not set QA disposition. The separate provider CSV remains `FAIL` for this scene, and the analysis hold remains active.

The sidebar uses the user-supplied horizontal EESAR Systems logo from the provided logo pack. The source JPEG is included unchanged; CSS crops its surrounding white margin for the compact sidebar placement. ECHO remains the distinct product identity.

Newly selected GCOV and OPERA pair records can also start an analyst-authored, unassessed investigation draft. The user records competing explanations and one falsifiable next observation tied to a single hypothesis, with expected, weakening, and inconclusive outcomes and explicit acceptance gates. The draft retains the exact submitted SAR JSON text and checksum; it preserves the actual provider QA and maturity state, makes no evidence relationship, and does not rank or retrieve the proposed observation. Up to twelve distinct staged sources can be screened against the same preregistered gates, with each source's analyst-entered results, inspection basis, limitations, timestamp, and checksum retained separately. The follow-up summary is `ANALYST_SCREENED_CANDIDATE` if at least one candidate has all gates marked met; otherwise it is `RETRIEVED_QUALITY_LIMITED`. These are analyst-declared states only: they do not authenticate a source, establish independence, change source QA/status, or evaluate a hypothesis. Drafts can be exported as JSON or saved as immutable, content-addressed snapshots in the user's private local data directory. Save and reopen validate the draft and recheck imported case links; local records are owner-readable, bounded, loopback-only, and remain outside the source repository. Snapshot hashes establish integrity, not authorship or scientific validity. See [Decision 0058](docs/decisions/0058-start-source-linked-investigations-from-pair-records.md), [Decision 0062](docs/decisions/0062-restore-exported-investigation-drafts.md), [Decision 0063](docs/decisions/0063-record-analyst-followup-screening.md), [Decision 0064](docs/decisions/0064-save-private-local-investigation-snapshots.md), [Decision 0103](docs/decisions/0103-screen-multiple-candidates-against-one-test.md), [draft workflow validation](docs/validation/investigation-draft-workflow-2026-11-08.md), [restore validation](docs/validation/investigation-draft-restore-2026-11-08.md), [follow-up screening validation](docs/validation/investigation-followup-screen-2026-11-08.md), [multi-candidate screening validation](docs/validation/multi-candidate-followup-screening-2026-11-09.md), and [local persistence validation](docs/validation/local-investigation-draft-persistence-2026-11-08.md).

When staging an additional source, an analyst can declare whether it derives from or shares observations with records already in the draft. ECHO validates that linked IDs exist and that derivation links are acyclic, then exposes each link in the source list and opens the linked record in the inspector. These declarations are explicitly unverified; missing lineage does not establish independence. See [Decision 0105](docs/decisions/0105-record-declared-lineage-in-investigation-drafts.md) and [lineage validation](docs/validation/investigation-draft-lineage-2026-11-09.md).

The draft can stage user-supplied JSON records as unreviewed, or import direct evidence records from the active ECHO case after validating its assessment, manifest links, paths, and checksums. Case imports require exact OPERA RTC-S1 before/after scene IDs matching the case assessment; records with declared derivation or shared-observation links are excluded. The absence of recorded links does not establish independence. Imported records preserve their case role and status and are labeled **case record integrity validated; provider not reverified**. An explicit analyst-assessment step records source fit for the stated hypothesis, relationship, review basis, rationale, and limitations. Directional relationships require the analyst to declare the source suitable for that scope; the declaration is not independently validated. ECHO derives a scoped disposition using its deterministic relationship rule and labels it **analyst-assessed, unverified**. Provider quality, source suitability, independence, reviewer identity, and scientific interpretation are not authenticated by draft import or analyst assessment. Directional relationships are rejected for QA-held, product-maturity-held, descriptive-only, or diagnostic SAR records. These are provisional review records, not validated scientific findings; see [Decisions 0059–0061](docs/decisions/0059-stage-unreviewed-sources-in-investigation-drafts.md), [the assessment workflow validation](docs/validation/investigation-analyst-assessment-2026-11-08.md), and [case-evidence import validation](docs/validation/investigation-case-evidence-import-2026-11-08.md).

## Data and licensing

No radar pixels or other large data products are included. The case JSON is ASF catalog metadata only. Data attribution, redistribution terms, and the repository license remain to be assessed before adding derived or source data. The repository is private during development.
