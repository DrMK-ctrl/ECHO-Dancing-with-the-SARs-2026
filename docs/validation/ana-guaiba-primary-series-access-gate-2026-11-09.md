The legacy query and current inventory miss do not establish that the archive is absent.

No access request was sent, and no personal identifier or credentials were collected. The assessment still does not represent gauge values as retrieved evidence; the later bounded `87450020` access screen is recorded separately below. The series screen retains the official source references and exact requested SAR timestamps. It keeps emergency station `87444000` separate from corrected station `87450020` and forbids unjustified interpolation.

## Additional public-route screen — 2026-11-09

Two public state-level routes do not currently resolve the historical-series dependency. SEMA's [hydrometeorological data access page](https://www.sema.rs.gov.br/niveis-guaiba), published in May 2024, points to a historical-download portal at `saladesituacao.rs.gov.br`; an HTTPS request to the named host failed DNS resolution during this screen. This is an access failure for that portal, not evidence that its archive lacks the readings. The current [Defesa Civil RS hydrometeorological API guide](https://sistemas.defesacivil.rs.gov.br/api-redehidrometeorologica) states its `historic` endpoint is limited to the most recent three months, so it cannot retrieve this case's May–June 2024 readings as of this screen. Neither route supplies a substitute series for station `87444000`.

The current supported route for the original-reference series remains ANA's authenticated HidroWebService. Its documented access process requires an application with the user's CPF/CNPJ and email. No request was submitted and no personal identifier was collected. The data-access state for station `87444000` remains `ACCESS_REQUIRED`; no values, evidence relationships, or hypotheses changed.

## Bounded retrieval from the corrected station — 2026-11-09

A distinct, currently responding public route was screened after the access-gate note was written: ANA's legacy `ServiceANA.asmx/DadosHidrometeorologicos` endpoint returned HTTP 200 for station `87450020` on both T163 SAR calendar dates. Each bounded response contains 96 records, at 15-minute intervals, with `Nivel` values and timezone-free `DataHora` strings. The exact requests, retrieval times, response hashes, returned timestamp bounds, and retained XML payloads are recorded in [`ana-serviceana-corrected-guaiba-screen-2026-11-09.json`](../../data/research/ana-serviceana-corrected-guaiba-screen-2026-11-09.json).

This is the corrected station identifier and series documented by ANA/SGB; it is not the emergency reference series `87444000`. ANA states that its legacy service was extended only through 2026-06-30 and redirected to a secondary database with possible update delay. It still responded during this screen, but that does not make it a supported current archive route. The retained legacy API manual identifies the `DataHora` field but does not specify its timezone; the response also provides no per-reading QA status. Therefore ECHO does not align these records to the SAR acquisition instants, convert or label the `Nivel` unit, import them into the T163 assessment, or use them to validate a SAR boundary. The new route establishes that bounded values are retrievable from the official endpoint, while the original-reference `87444000` access gate remains unresolved.

The next defensible step for time-aligned gauge evidence is to obtain authoritative timestamp semantics and series disposition from ANA/SGB or use the authenticated current HidroWebService after the required account access is granted. Until then, the retrieved XML remains a provenance-preserved access-screen artifact, not accepted investigation evidence.

## Public SEMA/RS–SGB report candidate — 2026-11-09

A public dashboard titled **Medições do nível do Guaíba — Usina do Gasômetro** was found through the DRHS/SEMA-branded [2024 monitoring page](https://linktr.ee/niveisguaiba2024), which links to a [Power BI report](https://app.powerbi.com/view?r=eyJrIjoiYWNhZDg0MDgtNWI5Ni00NjU3LTgyNDctYjgyOTE5MDFiMWM0IiwidCI6IjE1ZGNkOTA5LThkYzAtNDBlOS1hMWU1LWNlY2IwNTNjZGQxYSJ9). A live browser screen showed an hourly table labeled `Data e hora` and `Nível (m)` and a date-range control spanning 2024-05-03 through 2024-07-31. The report itself attributes the measurements to a SEMA/RS–SGB partnership and states that readings through 21:00 on May 4 came from the emergency staff gauge; from 22:00, an automatic sensor at that location was used and its levels were tied to the staff gauge. The report says the Gasômetro levels were transferred to the historical CAIS MAUÁ C6 reference because the Cais station was inaccessible, and therefore replaced that station during the emergency. It also records a 7 cm sensor adjustment from 12:00 on May 9, 2024.

This is a promising public, independent hydrologic context route, but it is **not** the original uncorrected `87444000` series: the dashboard reports values transferred to the CAIS MAUÁ C6 reference. The visible row labels omit timezone and year, no raw export or source-side quality flags were obtained in this screen, and the table view is capped at 500 rows. No row values were retrieved into ECHO or aligned to SAR acquisition times. The dashboard therefore remains a source candidate only; it does not change the ANA `ACCESS_REQUIRED` state, supply accepted gauge evidence, or support a directional relationship. Do not merge its reference with station `87444000` or the separately screened `87450020` series.

The SEMA page [Acesso aos Dados Hidrometeorológicos](https://www.sema.rs.gov.br/niveis-guaiba) independently describes its historical-data portal and current ANA telemetric route. The exact 2024 dashboard link is published by the DRHS/SEMA-branded monitoring page; the report's own statement of partnership is retained as reported provider attribution, not independent confirmation of each sample's quality.
